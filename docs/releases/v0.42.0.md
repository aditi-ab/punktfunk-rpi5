Wire-compatible with 0.41.0: a new client streams from an old host and the other way round, so you can update one side at a time. On Windows the installer updates the host and its drivers together.

- **Controller mouse gains a Touchpad mode.** The game keeps the controller while its touchpads move the host's pointer, on a DualSense, DualShock 4, Steam Deck or Steam Controller.
- **The Linux client is redesigned after the Mac,** with Hosts and Library tabs and a page per host, and decodes in hardware on ARM devices such as the Steam Frame and Raspberry Pi 5.
- **Desktop clients keep up at high frame rates again.** The last release decoded one picture at a time on AMD and NVIDIA GPUs, so a 4K stream at 120 fps or more fell behind, and automatic bitrate misread the decoder and dropped to its floor.
- **Emulators are ready on first launch.** The host answers their setup questions, puts firmware in place and, on Linux, binds the streamed controllers.
- **Windows clients on AMD GPUs pace to the screen.** They read its refresh, so variable refresh is detected and Smoothness no longer snaps frames to an invented beat.
- **Moonlight works better with punktfunk hosts.** Android Moonlight plays audio, Moonlight V+ connects with its mic on, a still Windows desktop shows its first picture, and a lost frame no longer smears the picture.
- **Game Mode stays intact after streams.** A SteamOS, Bazzite or CachyOS box no longer drops to the desktop, signs Steam out or asks for its language again.
- **A Windows host with its TV in standby streams.** The host wakes the display instead of starting a session that never shows a picture.

## New

### Every client

- **Touchpad in controller mouse.** Controller mouse on the dial now steps Off, Touchpad, Full. Touchpad keeps the controller in the game and moves the pointer with its touchpads: a DualSense or DualShock 4 like a laptop trackpad, a Steam Deck or Steam Controller pointing with the right pad and scrolling with the left. A tap never clicks, so a resting thumb fires nothing. Full is the whole-controller mouse, one press further on.

### Linux client

- **Hosts and Library are tabs,** at the bottom of a narrow window. The Library has a chip for each paired host and pinned preset, sections you arrange with Customize, and scrolls a 10,000-title library without holding a widget per title.
- **A page for each host,** behind the card's ⓘ: name, address, port, Wake-on-LAN MACs, presets, pairing, power, clipboard sharing and a network speed test.
- **The console opens when a controller connects,** Always fullscreen keeps the app fullscreen, and `browse` links open a host's library.
- **A banner while you stream,** with Disconnect, which ends the session on the host too. Keyboard Shortcuts in the menu lists the window's keys.
- **Each Preferences row saves on its own,** so closing Preferences no longer overwrites what another window just saved. A host whose certificate changed asks you to pair again instead of reporting it unreachable.
- **Hardware decode on ARM.** On a Steam Frame, Raspberry Pi 5, Rockchip RK3588 board or Snapdragon X laptop the client decodes on the device's own video decoder and asks the host only for what it takes. An aarch64 Flatpak installs it. It is tested against the kernel's reference decoders, not yet on each device; the Linux on ARM page lists what each one decodes.

### Android

- **Swap screens.** On a dual-screen handheld the picture and the companion panel trade screens, from the dial, the sheet or a panel tile. Each second screen remembers the swap, and an Automatic resolution follows the picture.

### Console

- **Power leads Host details.** Sleep host is five presses from the card on a remote, and Shut down eight.

### Apple

- **The .ipa on the release page is for sideloading.** AltStore, SideStore and Sideloadly sign it with your Apple ID. Wake-on-LAN and the widget's host list still need the App Store build.

### Emulators

- **Ready on first launch.** Before a game starts, the host answers each emulator's first-run questions — the PCSX2 and DuckStation setup wizards, Dolphin, Cemu and RPCS3 — and puts the platform's firmware in place, so a RomM title plays on a fresh host.
- **Streamed controllers are bound, on Linux hosts.** Eden, Azahar, Dolphin, melonDS, Cemu, PCSX2, DuckStation, RPCS3 and RetroArch get the session's pads in seat order before each launch, and their own bindings come back afterwards.
- **More managed emulators on Linux:** RPCS3, Xenia Canary, shadPS4 and Supermodel.

## Improved

- **Linux and Windows clients decode ahead.** On AMD and NVIDIA GPUs the next picture starts while the last one finishes, so 4K at 120 and 165 fps keeps up. Intel keeps its own path.
- **Automatic bitrate reads a decoder that works ahead.** It no longer rides the lowest rate on an AMD client at 4K 165 Hz, and no longer doubles the rate into an encoder limit it just backed away from.
- **Windows clients on AMD GPUs read the screen's refresh.** Variable refresh is detected, including a FreeSync screen at half its rate, Smoothness no longer snaps frames to an invented beat, and a stream at the screen's top rate no longer queues two frames deep.
- **Lowest latency on a variable-refresh screen** holds each frame a moment to even the spacing. Repeats of a still picture are shown, so the screen no longer slots its own refresh ahead of the next real frame.
- **Smoothness no longer sends frames in pairs** when a stream runs below the screen's refresh rate.
- **Loss heals faster** for a client that asks for a repair and a keyframe at once: a Mac on H.265 recovers about 300 ms after a loss instead of up to 3 s.
- **Trackpad scrolling holds its axis on every host.** A vertical two-finger scroll no longer drifts sideways or jumps up before it goes down.
- **GNOME and sway hosts scroll Firefox and GTK apps smoothly** from a Mac's smooth wheel, a controller or an older client's trackpad, instead of in stepped lines.
- **Windows hosts no longer nudge the pointer** to wake the desktop, and the first stream to a still desktop shows its picture at once.
- **Windows UAC and firewall prompts name punktfunk** and its publisher instead of a file name.

## Fixed

- **Moonlight audio:** Android Moonlight plays sound with GameStream encryption off or video-only. Moonlight V+ connects with its mic setting on, plays PCM passthrough, and has sound on a 7.1.4 device. Play audio on host keeps the sound on the host. moonlight-web-stream connects and plays clean audio.
- **Moonlight picture:** a still Windows desktop shows its first picture instead of black, a lost frame waits for a clean keyframe instead of smearing, and a lost keyframe request is answered. Moonlight's loss reports now raise error correction and lower the bitrate, and a host offers only the codecs it can encode.
- **Moonlight pairing and launch:** a host name with `&` or `<` no longer makes the host look offline, a wrong PIN reads as Incorrect PIN, and a refused launch says why. A shortcut to a removed game is refused instead of opening the desktop, and Wake-on-LAN reaches a host with several network cards, a VPN or Docker. On Windows hosts a held key repeats; on sway, Hyprland and river, touch drives the pointer.
- **Game Mode (SteamOS, Bazzite, CachyOS):** the host's own session starts no longer count toward Game Mode's crash limit, which dropped the box to the desktop, signed Steam out or asked for language and timezone again. Steam gets up to 8 s to quit before a takeover or hand-back, so its settings survive. A reconnect that fails its handshake, and every Moonlight session, hands Game Mode back. A slow start no longer ends the login, and a takeover is refused with less than 600 MiB free, where a session start would delete installed games.
- **Linux hosts:** stopping or updating the host mid-stream turns Hyprland and sway monitors back on and removes its virtual displays. The virtual microphone becomes the default only during a stream, so local apps no longer record silence, and a crash no longer loses your own default. A KDE or GNOME host no longer sleeps mid-game while a stream runs in its own gamescope. End game on a Steam title started while Steam was closed ends the game, not Steam. With no stream running, a screen share on sway goes to your own chooser.
- **Windows hosts:** a host whose only screen is a TV in standby wakes it and streams; if Windows keeps it dark, the client says so. AMD hosts fit a very high bitrate under the encoder's limit instead of refusing the session.
- **Emulators on Linux hosts:** a Flatpak emulator opens a ROM on a share such as `/mnt/games`, and a folder game (PS3, Wii U) gets its whole folder, read-only for that run. RPCS3 and PCSX2 start inside the host's own gamescope on a desktop instead of aborting, and a session whose game exited ends instead of streaming the desktop.
- **Nix:** host builds work again. They had failed since managed emulators arrived, so `nix-stable` still held 0.40.0.
- **Desktop clients:** a fullscreen stream no longer goes black when focus moves to another monitor, the capture hint hides while another window has focus, and the Windows client no longer spins a core while it holds a frame. A client asks for HEVC and 10-bit only where a hardware decoder takes them, so a first session no longer drops and redials.
- **Linux client on Intel:** H.265 over Vulkan Video no longer aborts after about 12 minutes on Mesa 25.2 to 26.2.
- **Console:** covers decode near the view instead of walking the whole library, and a TV keeps fewer in memory, so a large library no longer runs a TV out of memory.
- **iPhone and Android phones:** aspect ratio choices wrap to a second line instead of squeezing or hiding.
- **Android TV:** the console no longer shows block corruption on TVs such as the TCL P7K.
- **Apple:** the Mac no longer crashes when the audio device changes mid-stream, and a rare crash while presenting video, seen on iPad, is fixed.
- **Web console:** an installed Art & Metadata plugin that never started keeps its row, with a Running or Stopped badge and a pointer to Logs. 1Password fills the console password into the approve dialog instead of the field behind it.
