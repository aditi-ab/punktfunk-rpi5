Works with 0.44 hosts and apps, in either order. If you stream PyroWave, update the apps with the host.

- **Stream to every monitor.** Set **Screens** to **All monitors** in the Windows, Linux or Mac app, and each monitor gets a screen of its own from the host, laid out as your monitors sit.
- **Windows PCs that couldn't open a stream now can.** Snapdragon X laptops and older Intel graphics such as the HD 4000 draw through Direct3D 11, with hardware decode for HEVC, AV1, 10-bit and HDR.
- **The Steam Deck stops skipping a frame and doubling the next.** Frames on a fixed-refresh screen land on an even beat, in Lowest latency too.
- **A dropped link no longer ends the stream.** Every app dials the host again five times over about 15 seconds, and phones follow a switch from Wi-Fi to cellular at once.
- **Linux NVIDIA hosts send HDR with full colour detail (4:4:4).** Every host now sends full-range colour, so dark gradients keep every step.
- **Vision Pro curves the screen.** Eight curves from Flat to 800R, a Spatial audio switch, and controls that rest as a small bar.
- **Android shows 120 fps at 120 Hz** on tablets and phones that held it at 60, and plays 5.1 and 7.1 on every speaker.
- **PyroWave needs about a fifth less bandwidth.** A frame that loses its end shows with a small blur instead of being dropped, and Moonlight forks can stream PyroWave too.

The Linux and Windows apps change their app IDs. The Flatpak moves on its own; a Windows MSIX install needs the old package removed first. See Before you update.

## Before you update

- **PyroWave: update the apps with the host.** A 0.45 host puts PyroWave's repair data at the start of each frame only. A 0.44 app drops a frame that loses part of its end; a 0.45 app shows it with a small blur.
- **Linux: the app IDs are lowercase.** The Flatpak, desktop files, icon and window app ID are now `io.unom.punktfunk` and `io.unom.punktfunk.host`, as on Apple and Android. Stable Flatpak installs move to the new ID on the first `flatpak update` after this release. Re-pin launchers, and change compositor window rules that match `io.unom.Punktfunk`. GNOME lists the windows again after your next login.
- **Windows MSIX: remove the old package first.** The MSIX is now `io.unom.punktfunk` and installs beside `unom.Punktfunk` instead of replacing it. Run `Get-AppxPackage *unom.punktfunk | Remove-AppxPackage`, then install. The setup program and winget need nothing.
- **Linux hosts reachable without logging in: re-enter display and hook changes.** Display policy and hooks saved while the door was on never took effect. They now live on your own host; set them again there.
- **Seats with a hand-made firewall:** a browser streaming to a seat needs UDP 9783–9786. The shipped ufw, firewalld and NixOS rules carry it: run `sudo ufw app update punktfunk-native && sudo ufw reload` or `sudo firewall-cmd --reload`.
- **Arch, hand-built system extension:** the host image is now `punktfunk.raw`, the name Bazzite uses. Delete `/var/lib/extensions/punktfunk-host.raw` before copying the new one.

## New

### Screens

- **Stream to every monitor.** **Screens** → **All monitors** opens a fullscreen window on each monitor, one host screen each. A monitor plugged in mid-stream joins, and closing a window gives its monitor back. The host draws the pointer on the further screens. Needs a host that builds its own displays (not gamescope). In the Windows and Linux apps, the console and the Mac app; a preset can carry it per host.
- **Extra resolutions on Windows hosts.** The virtual display offers common sizes beside the stream's own, so a game can run at 1440p on a 4K stream. Change the list under **Extra resolutions** in the web console's advanced host settings.

### Apps

- **Direct3D 11 on Windows.** A PC whose Vulkan driver can't show hardware-decoded video picks Direct3D 11 at stream start. It paces frames to the screen's real refresh, shows HDR on an HDR display, and the stats overlay names the path.
- **The Mac app runs on Intel Macs again.** One universal download for macOS 14 and newer, and the Mac App Store build reaches Intel too.
- **Mac: a warning for macOS 26 on a variable-refresh display.** macOS 26 stalls a stream there for hundreds of milliseconds at a time; the stream-start notice names the setting to change. macOS 27 is fine.
- **Vision Pro: a curved screen.** The **Screen** setting bends the picture through eight curves from Flat to 800R, from Settings, the console or a slider on the stream controls. Pinches, the quick-action ring and the stats lie along the curve, and **Match window** fills the curve at whatever shape you give it.
- **Vision Pro: quieter controls.** The stream controls show for a few seconds, then rest as a small bar; look at it to open them. The window has square corners, like a monitor.
- **Vision Pro: Spatial audio switch.** On by default; off plays the game's own mix straight to your ears. The refresh list offers 120 Hz.
- **Linux and Steam Deck: shared clipboard.** **Share clipboard** now works on every Wayland desktop, GNOME included, and on X11.
- **Linux: the Flatpak keeps its settings in its own sandbox.** It copies older pairings over on first start, and About shows the package's real version.
- **The codec can change mid-stream.** When the host changes codec, bit depth or colour, every app rebuilds its decoder and carries on. On Windows and Linux a failing decoder asks the host for another codec instead of ending the stream.
- **Waiting for approval.** A connect to a host that doesn't know the device shows the waiting screen until someone approves it, instead of timing out on Connecting.
- **Guests see covers and can end games.** Posters, status, game actions, profiles and log uploads use the stream port first, so a guest with TCP 47990 closed gets the whole library.
- **Bitrate stays Automatic or Fixed under PyroWave.** Fixed holds the session at the quality you picked; Automatic follows the network.
- **Android: the log survives a crash.** **Send logs to host** after a relaunch carries the crash.
- **Android: a slow first start is remembered.** A device whose decoder needs a fallback keeps that choice, saving about five frozen seconds on every start.

### Hosts

- **Full-range colour on every stream**, SDR and HDR, 8 and 10 bit.
- **Linux NVIDIA: HDR with 4:4:4.** A client that asks for both gets both.
- **Jumbo frames turn on by themselves** when the host's and the client's network adapters are both set above MTU 1500. The host still tests the path and falls back if a switch can't carry it.
- **PyroWave for Moonlight forks** that speak its GameStream extension, on Linux and x64 Windows hosts.
- **Seven more stores on the shelf:** Amazon Games, Battle.net, the EA app, Ubisoft Connect, the Rockstar Games Launcher and itch on Windows; itch and Bottles on Linux.
- **Fedora 45 and Bazzite 45** have packages and system-extension feeds. After a major Bazzite rebase, fetch the update script again, as the update guide says.
- **Browsers can stream to a seat** through a host reachable without logging in.
- **Windows: profiles that take turns.** **Add profile** → **Own account (take turns)** binds a profile to a local Windows account, which takes the PC's one desktop in turn. Any Windows edition works: no Windows Server and no Remote Desktop licence. The account must have signed in on the PC once.
- **Windows seats: desk controllers stay at the desk.** A guest's seat no longer reads the controllers plugged into the PC. **Players keep their controllers** (on by default) keeps a seat's game from losing its pad when another session switches apps.

## Improved

- **Steam Deck and fixed-refresh screens:** each frame is shown at its due time, and the pacing learns the panel's real refresh, so a Deck set to 60 Hz on a 90 Hz panel no longer mis-aims.
- **PyroWave** packs each frame tighter (about a fifth less bandwidth) and costs less CPU to receive on Android, desktop and Apple. Its bitrate matches what the quality slider shows, so 4K60 10-bit no longer overruns gigabit Ethernet.
- **Windows NVIDIA hosts:** about 2 ms less latency at 4K120; the encoder reads each frame where the display driver left it.
- **Windows hosts under loss:** the display driver's encoders stop referencing frames the client hasn't confirmed, so a lost frame costs fewer repair round trips.
- **Linux NVIDIA with gamescope:** frames go to the encoder without a copy, so a GPU-bound game holds 120 Hz.
- **A still Linux desktop** re-encodes at a quarter of the refresh rate, so GPUs and battery-powered clients run cooler.
- **Android:** Latency mode no longer holds every frame an extra refresh (15 ms instead of 22 ms at 120 Hz); **Native** refresh means the panel's highest, so a 165 Hz tablet asks for 165; PyroWave goes straight to the screen compositor, saving up to 2 ms of CPU a frame.
- **Mac:** PyroWave reaches 4–5 Gbit/s again instead of topping out near 1.7.
- **Apple:** less CPU per frame, and the first connect after launch is quicker.
- **Windows and Linux apps:** hardware decode hands frames on the moment they are ready, and the Vulkan window waits for Direct3D 11 decode on GPU fences instead of a lock.
- **Rumble** reaches the controller at once on desktop and Apple.
- **Encryption** runs about twice as fast on x86 PCs.
- **Automatic bitrate:** a decoder that runs over its frame budget, such as H.264 at 4K120 on a PS5, no longer drags the rate to the floor; a host rebuild no longer reads as congestion; PyroWave no longer loses quality when host encode time rises.
- **Networks:** the host keeps watching the path, so a client that moves onto a VPN gets its video shrunk to fit at once. A host stops batching sends on a path that loses them.

- SteamOS seats get their own plugin runner, and a Bazzite update restarts the door and the seat service.
- NixOS: the door switches off cleanly, and the owner's host gets the module's settings, so Moonlight stays up when the owner leaves the desk.

### Windows host

- Two clients sharing one identity, or two Moonlight clients, no longer take each other's display, and a device that joins a display shares it instead of freezing the first stream.
- Intel UHD 630 encodes HEVC.
- 10-bit SDR no longer stays off after a resize the display refused.

### Every host

- Asking for the mode already running no longer rebuilds the stream.
- A slow capture gets its full wait after a loss instead of ending the session.

## Security

- **Web console:** a path with an encoded slash or question mark could reach admin routes on a box with seats; seat answers are now JSON or images only, under a sandbox policy.
- **Paired devices** can no longer read the host's account name or a failed seat's details, or queue unbounded wake threads.
- **Linux seats:** an occupied seat refuses a device the box wouldn't let share the screen; seat homes are closed to other seats; the Steam copy skips Steam Guard tokens; the shared games folder can't be renamed or linked; the door runs as its own user and keeps a console limited to this machine.
- **Windows seats:** the seat service answers only on a pipe the system owns, and turning seats off restores each Remote Desktop firewall rule's scope.
- **Host memory:** an unpaired device can't hold its approval wait open past its limit, and a client repeating feedback or acknowledgements can't grow the host's memory.
- **Roaming:** video follows a client to a new address only after the address answers, so a spoofed packet can't aim the stream at someone else.
- **Windows:** the Moonlight ports open only while GameStream is on.
- **Android:** a copy a password manager marks sensitive stays off the host's clipboard.
- **Dependencies:** certificate checks no longer accept distrusted intermediates or emSign roots, two crypto libraries close timing leaks, and the web console, the docs site and Bun move past this month's advisories.
